TUI 与 GUI

2026/09/21AI学习

TUI和GUI的区别，相信很多人会认为：这只是习惯问题，有的人喜欢图形化操作，有的人喜欢命令行。

最开始的我也是这么想的，但是这个理由比较片面与理想化，所以通过查阅一些文档以及与LLM交流，得到了以下的答案：

‍

TUI的好处

‍

可组合性（TUI 独有，GUI 追不平）

等于说，TUI agent保留了终端的所有功能，而GUI agent无法像TUI agent一样灵活，虽然有其他实现方式，但是依旧不如原生。

‍

原始会话记录留档（TUI可直接产生无损会话记录，GUI需要做有损清洗）

TUI agent的输出内容本身就是完整、有顺序、纯文本、可无损还原的会话记录，而GUI agent为了更好地可读性和功能，会将会话渲染成组件（可折叠的工具调用块、ANSI颜色码渲染的文本，充当表格的框线、流程图渲染等等），这些内容对于LLM来说都是无用信息，所以在留档时必须做清洗，但是清洗是有损的，操作不当会破坏重要信息。

这点也是我个人觉得目前来说最有用的一点之一，尤其是做前端动画的时候。在最初我在GUI上做代码修改时，只会留下会话摘要，不会留档会话记录，这就导致，在未来修改动画时，LLM只能通过摘要知道当初做了什么，但是不知道为什么这么做，以及其他的一些踩坑——这本身就是摘要正确的做法，只留关键词让LLM去会话记录中去匹配，只是当时并没有留档会话记录，所以只发挥了摘要一半的作用。

[!WARNING] ⚠️ 即使TUI本身输出的就是无损的会话记录，也要做转换 TUI原始的内容是JSON字符串，而保留完整的JSON就会占用更多的磁盘空间，LLM在匹配时也会匹配到一堆无意义的json格式，所以需要转换。而且像是Claude code 的会话记录本身是有过期时间的，所以需要我们自己手动转换保存下来。

同时，TUI虽然本身是无损的会话记录，但是还是要根据我们自己的需求来做过滤，比如系统提示/元数据，也是无用信息，可以删了。这点不管是TUI还是GUI都是要做的，只是TUI原始会话记录比GUI干净得多（点名workbuddy，默认情况下每个问题都会给你生成个流程图）。

‍

完整查看LLM输出内容

这点用过Codex的人估计都能明白，Codex会隐藏思维链，只给用户看正文结果。而Claude Code Cli 可以通过​ctrl + o来查看完整输出，这点就非常舒服，尤其是完善工作流方面，能够直观地看到模型到底在想什么。

当然，不是所有的GUI都是隐藏思维链，但毋庸置疑，这点来说还是TUI更好一点。

‍

‍

GUI 的好处

‍

更清晰、可读性更好的阅读体验

像是diff界面、git树、文件列表，代码上下文发现等等，这些都是GUI集成的功能，在使用上更加方便，而TUI想要做到的话就需要装成插件，比如说vscode里的claude code 插件，通过这种方式来集成。

‍

更多内置功能，更方便地添加插件

很多GUI都有可视化的插件市场，内置浏览器，这些对于TUI来说都需要自己去配，无法像GUI一样那么直观。

‍

区别不大的地方

像是MCP操作浏览器，虽然TUI不能像部分GUI一样有内置浏览器可以直接操作，但也可以安装​playwright插件来实现（Codex的内置浏览器底层也是用这个实现的）。以及GUI更好上手这方面我个人感觉区别不大，多碰碰就能适应。

‍

‍

总结

TUI和GUI很多时候并不是二选一，而是混合使用，像我现在就是codex桌面端 + claude code cli 混合使用，两者各有各的好处，但这又好像回到了最开始说的个人喜好上，嗯，确实仁者见仁，智者见智吧。
