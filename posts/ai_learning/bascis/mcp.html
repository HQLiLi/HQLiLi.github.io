MCP 是什么 / 解决什么问题

MCP 是一个协议，主要是解决以前每个服务都有自己的配置的情况，就比如说你接 A 服务，它有自己的标准，接 B 服务，他也有自己的标准，这样就变得很混乱。

当然，这里最难受的不是配置的问题，因为这部分各家都长得差不多（URL+token），最麻烦的是 runtime 集成代码。以 Github 为例：

  • 在没有 MCP 以前，如果要在 Codex、Claude Code、Cursor 中接入 Github 的外部服务，每个都要写一份自己的实现，这样就等于一下子写了 3 份
  • 有了 MCP 之后，Github 写了一个 MCP server，所有 AI 主机只需要用同一份实现就能连接

也就是说，这个有点类似于 JDBC（Java 连接数据库）

MCP 主要定义了哪三件套

MCP主要定义了三件东西：

协议概念谁主动发起干啥
ToolsAI（Client）调 server跑函数 / 执行操作
ResourcesAI 读 server 的资源拿只读数据 / 上下文
Prompts用户从 server 预制模板里选让 AI 按模板走一遍流程

MCP Tools 与 skills 的相似之处

我们主要说一下 MCP Tools，这玩意跟 skills 一样，harness 会将 MCP 名单也给 AI，里面也有 description​，AI 根据这个来匹配是否要调用 MCP tools。

插件 ≠ MCP:两者什么关系

说句题外话，我之前一直认为插件就是 MCP，但是实际了解下来却并不是我想的这样，这点也可以在 Codex 设置里的插件选项中可以看出来，MCP 和插件是分开的。

插件，准确的来说他是一个打包单元，里面可能有 skill、MCP 接入配置，以及 prompts 之类的东西。
