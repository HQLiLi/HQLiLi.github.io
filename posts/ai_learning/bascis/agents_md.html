Agents.md篇

2026/08/30AI学习

2026.8.30 19:25

在知道了 skills 的工作原理后，agents.md 就变得很清楚了。

首先 agents.md​ 全文常驻上下文，而 skills 只会名单常驻，正文是在 AI 匹配到 skill 后才会注入。因此，它里面更适合存放一些"每句话都适用的规范和约束"，以及AI 猜不到的项目事实（源码在哪、测试怎么跑、构建命令）。

就比如说我的 C++ Native 项目中 Trellis 初始化的 agents.md，除了 Trellis 对 AI 的约束，告诉它哪些目录存放着哪些信息以外，还有我在写代码时让它往里添加的内容，比如下面的：

## crengine 参考约定（重要）

- **crengine 项目本地已有，无需联网搜索**：源码位于 `f:\learning_projects\android_porjects\crengine-master\crengine\`（只读参考，任何修改需走外部流程）。
- **与 crengine 相关的问题，先查项目内已记录的文档**，再决定是否读源码：
  - `.trellis/spec/android/crengine-reference.md` — 总览（含源码根、分篇入口、引用规范）
  - `.trellis/spec/android/crengine-epub.md` / `crengine-css.md` / `crengine-block-layout.md` / `crengine-text-layout.md` / `crengine-render.md` — 按链路分篇
  - `.trellis/tasks/08-08-crengine-tech-reference/research/` — 源码锚点核对记录
  - `.trellis/tasks/*/research/*crengine*` 及 `.trae/documents/` — 各任务沉淀的 crengine 相关研究/修复记录
- 源码行号会漂移，引用时优先用 `文件:符号名`（如 `lvtextfm.cpp:LVFormatter::format`）而非裸行号。

## AI 行为约定

- **Git commit 默认不自动提交**：AI 助手在完成代码 / 文档 / 配置改动后，**不要主动执行 `git commit`**（包括 `git commit -m ...`、`git commit -F`、amend、rebase、push 等任何写入历史/远端的命令），除非用户在**同一对话回合中显式说明**（如「帮我 commit」「提交吧」「git commit 一下」等措辞）。仅 `git status` / `git diff` / `git log` 等只读命令不受此约束。
  - 实施流程应停在「改动完成 + 通过验证 + 给出文件清单 + 列出建议的 commit message 草稿」状态，等用户自行审查与提交。
  - 计划（plan）中包含 commit 步骤不代表授权执行——commit 仍需用户在执行回合显式确认。
  - 已有的本地未推送 commit 不主动撤销；若用户要求撤销，使用 `git reset --soft HEAD~1` 等可逆命令并先报告。
  - 「之前的 Trellis 偏好」中提及「commit changes`[required · once]`」等模板步骤应解读为**描述工作流**，**不**等同于授权执行 commit。

第一个 crengine​ 的参考约定是因为我让 AI 已经生成了一个功能记录文档，里面详细地写了 crengine 的哪些功能是如何实现的，而在这个功能上与我们自己项目的差异或者是否已经实现，这样就会减少 AI 在初步定制方案的时间。

而第二个约定行为是因为我不喜欢 AI 自动提交，我喜欢经过我代码审查完后再手动提交。

但是说实话，crengine​ 这段还可以简化，可以只告诉它 crengine​ 源码本地就有，并告诉它路径，然后将其他的内容做成一个 skill，在 agents.md​ 里加一句：crengine​ 相关的工作遵循 crengine skill。
